Git Basics Validation

Before diving into branching strategies, let’s verify your Git environment is working correctly.

Run the commands in the OpenShift Web Terminal provided by the workshop environment. The Web Terminal includes the required CLI tools and avoids local workstation prerequisites.

Step 1: Access GitLab

First, verify you can access GitLab through your browser.

Get the GitLab URL and open it in your browser:

GITLAB_URL="https://$(oc get route -n gitlab -l app=webservice -o jsonpath='{.items[0].spec.host}')"
echo "Open this URL in your browser: $GITLAB_URL"
Login Process

  1. Click the "ETX Lab SSO" button (SSO login)

  2. You’ll be redirected to Keycloak authentication

  3. Login with workshop credentials:

    • Username: {user}

    • Password: {password}

Workshop Users Available:

  • platform-admin - Administrative access

  • platform-user - Standard user access

  • platform-developer - Developer access

All users use password: openshift

After login, you should see the GitLab interface with the software-factory group.

Step 2: Clone the Workshop Repository

Now clone the ETX App Base application repository using Git CLI.

First, get the GitLab URL:

# Get GitLab URL dynamically
GITLAB_URL="https://$(oc get route -n gitlab -l app=webservice -o jsonpath='{.items[0].spec.host}')"
echo "GitLab URL: $GITLAB_URL"

Then clone the repository:

mkdir -p ~/workshop
cd ~/workshop
git clone ${GITLAB_URL}/software-factory/etx_app_base_app.git
cd etx_app_base_app

Authentication for Git CLI:

When prompted for credentials during git clone, use your assigned workshop credentials or create a personal access token from GitLab: Settings → Access Tokens → Create token with read_repository scope
Expected Output
Cloning into 'etx_app_base_app'...
remote: Enumerating objects: 150, done.
remote: Counting objects: 100% (150/150), done.
Receiving objects: 100% (150/150), done.

Step 3: Verify Basic Git Commands

# Check repository status
git status

# View current branch
git branch

# View recent commits
git log --oneline -5
What You Should See

  • Current branch: main

  • Working directory: clean

  • Recent commit history displayed

If any of these commands fail, verify:

  • Git client is installed: git --version

  • Git is configured in the repository: git config --list --local

  • You have network access to GitLab

Step 4: Configure Git (If Needed)

If this is your first time using Git on this system:

git config user.name "Platform Developer"
git config user.email "platform-developer@example.com"
These commands configure Git only for the current repository. Use git config --global only on a workstation or bastion environment that you own and intend to reuse. Replace the name and email with your actual identity.

Validation Complete - You’re ready to work with branches.

Branching Models

Different teams use different branching strategies based on their release cadence, team size, and deployment practices.

Trunk-Based Development

Trunk-Based Development is a lightweight strategy where developers integrate small, frequent changes into main to keep the codebase continuously releasable and deployable.

Characteristics:

  • All developers commit to a single main branch

  • Short-lived feature branches (hours to days)

  • Frequent integration (multiple times per day)

  • Continuous Integration runs on every commit

  • Feature flags for incomplete features

Best suited for:

  • Teams practicing Continuous Delivery

  • Small to medium teams (2-10 developers)

  • Projects with automated testing

  • Cloud-native applications

Example workflow:

# Create short-lived feature branch
git checkout -b feature/add-validation

# Work, commit frequently
git commit -am "add email validation"

# Merge back quickly (same day)
git checkout main
git merge feature/add-validation
git push origin main
